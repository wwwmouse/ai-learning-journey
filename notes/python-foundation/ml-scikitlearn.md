# scikit-learn 机器学习实战笔记

基于 scikit-learn 的传统机器学习分类项目笔记，覆盖完整流程、核心函数、模型对比三大部分。

---

## I. ML 完整流程

一个完整的机器学习分类项目，分为以下 **7 个阶段**：

```
原始数据  →  探索  →  预处理  →  切分  →  训练  →  评估  →  调参/部署
  .csv      看懂     洗干净     分考场     学       打分       优化/保存
```

### 1.1 数据探索（EDA — Exploratory Data Analysis）

**目标**：理解数据长什么样，发现问题，形成直觉。

| 探索内容 | 函数 | 回答什么问题 |
|------|------|-------------|
| 前几行 | `df.head()` | 数据大概长什么样？列名有意义吗？ |
| 维度 | `df.shape` | 多少行（样本）？多少列（特征）？ |
| 类型 | `df.dtypes` | 哪些是数字？哪些是文字？哪些需要编码？ |
| 缺失 | `df.isna().sum()` | 哪些列有空值？比例多少？影响大吗？ |
| 统计 | `df.describe()` | 数值列的均值、标准差、最大最小值——有没有离谱的异常值？ |
| 分布 | `sns.countplot` / `sns.histplot` | 标签均衡吗？各特征的取值范围合理吗？ |
| 关系 | 按类别分组求均值 | 哪些特征和标签有强关联？（如：女性存活率远高于男性） |

**这一阶段只看不改。** 输出是图表和直觉，不是模型。

**常见发现**：
- 某个特征缺失率太高（>50%），直接删
- 标签分布不均（如 62% 死亡 vs 38% 存活）——评估时不能只看准确率
- 某个特征的值域太大（如 Fare 0~512）——需要标准化

---

### 1.2 数据预处理（Data Preprocessing）

**目标**：把原始数据变成模型能直接处理的纯数字矩阵。

通常有以下步骤：

```
删无用列 → 填缺失值 → 文字转数字 → 切分 → 标准化
```

#### 1.2.1 删除无用列

```python
df = df.drop(['PassengerId', 'Name', 'Ticket', 'Cabin'], axis=1)
```

删什么：
- **ID 类**（PassengerId）：每个样本不同，没有任何预测价值
- **文本类**（Name, Ticket）：不经过高级处理（NLP），模型无法理解非结构化文本
- **高缺失类**（Cabin 缺失 77%）：填也不是，不填也不是，删了最干净

`axis=1` 表示删**列**，`axis=0` 表示删行。

#### 1.2.2 填充缺失值

```python
age_median = df['Age'].median()
df['Age'] = df['Age'].fillna(age_median)
```

| 填充策略 | 适用场景 |
|----------|---------|
| 中位数（median） | 偏态分布（收入、年龄）——不受极端值影响 |
| 均值（mean） | 正态分布——和整体中心一致 |
| 众数（mode） | 分类变量（如 Sex ） |

**Age为什么用中位数而不是均值**：
假设 891 人里有 10 个 80 岁的老人，均值会被拉高，中位数不受他们影响

#### 1.2.3 文字转数字

```python
df['Sex'] = LabelEncoder().fit_transform(df['Sex'])
df['Embarked'] = LabelEncoder().fit_transform(df['Embarked'])
```

模型背后的数学是矩阵运算，只接受数字。`LabelEncoder` 做的事：

```
原始: ['female', 'male', 'male', 'female']
  ↓
扫描: 发现两个不同值 → ['female', 'male']
  ↓
按字母序编号: female=0, male=1
  ↓
输出: [0, 1, 1, 0]
```

**注意**：`LabelEncoder` 按字母顺序编号，不是按重要性。`female` 在 `male` 前面，所以 female=0, male=1


#### 1.2.4 切分训练集/测试集

```python
X = df.drop('Survived', axis=1)   # 特征矩阵：去掉标签列
y = df['Survived']                 # 标签列

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.3,
    random_state=42,
    stratify=y
)
```

**四变量含义**：

| 变量 | 角色 | 类比 |
|------|------|------|
| `X_train` | 练习题目的 | 平时作业（623 题） |
| `y_train` | 练习题目的答案 | 作业答案（对答案用） |
| `X_test` | 考试题目 | 期末考卷（268 题） |
| `y_test` | 标准答案 | 标准答案（密封，最后对分用） |

**为什么必须切分**：如果不分，用同一份数据又学又考，模型可能把题目全背下来拿 100 分，但碰到真正的"新题"就懵了——**过拟合**


#### 1.2.5 标准化（Feature Scaling）

```python
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)   # 训练集：计算参数 + 转换
X_test = scaler.transform(X_test)         # 测试集：只用训练集参数转换
```

**为什么要标准化：消除各特征值域的巨大差异，让所有特征在计算时有公平的初始权重起点**

| 特征 | 取值范围 | 不做标准化的后果 |
|------|---------|----------------|
| Age | 0 ~ 80 | 权重正常 |
| Fare | 0 ~ 512 | **主导模型**——Fare 的数字大 6 倍，**模型误以为它重要 6 倍** |

标准化公式（Z-score）：

```
新值 = (原值 - 列均值) / 列标准差
```

做完后每列均值=0，标准差=1，所有特征平起平坐。

**请注意，这里测试集和训练集用了不同的方法**
这是为什么呢？原因见下表：

| 操作 | 训练集 | 测试集 |
|------|--------|--------|
| | `fit_transform()` | **只能** `transform()` |
| 做了什么 | 自己算均值、标准差，再转换 | 用**训练集**的均值、标准差来转换 |

**不能用 `fit_transform` 对测试集**：`fit` 意味着"从这份数据里学统计信息"
在现实中**数据是分批到来的**，我们不可能提前拿到未来所有数据的均值与标准差
如果从测试集"学"它的均值和标准差，等于偷看考试数据——**数据泄露（data leakage）**：初学者常犯
类比：考试时只能用平时总结的经验去答题，不能当场分析考试卷子的统计特征。

### 1.3 模型训练

sklearn 所有模型遵循**完全相同的 API**，这是它最优雅的设计：

| 方法 | 作用 | 参数 | 返回值 |
|------|------|------|--------|
| `fit(X, y)` | 训练 | 特征矩阵 + 标签 | 训练好的 model 本身 |
| `predict(X)` | 预测 | 特征矩阵（不需要标签） | 预测结果数组 |
| `score(X, y)` | 评估 | 特征矩阵 + 真实标签 | 准确率（分类） |

**核心就是 `fit → predict → score` 三步**
无他，但手熟尔^^

### 1.4 模型评估

**只看准确率会被骗。**

例子：泰坦尼克 62% 的人死了。模型如果**闭眼全判死亡**，准确率 = 62%，看起来不错——但它一个活人都没找到，模型是废的。

综上所述，必须拆开分别看四个指标：

#### 1.4.1 混淆矩阵

以逻辑回归为例：
以"存活"（Survived=1）为正类（Positive），"死亡"（Survived=0）为负类（Negative）。
```
           预测死亡  预测存活
实际死亡     140       25       ← 165 个真死的人
实际存活      30       73       ← 103 个真活的人
```

| 格子 | 叫什么 | 含义 |
|------|--------|------|
| 140 | TN（真负类） | 判死，实际死了——正确 |
| 25 | FP（假正类） | 判活，实际死了——**误报** |
| 30 | FN（假负类） | 判死，实际活了——**漏报** |
| 73 | TP（真正类） | 判活，实际活了——正确 |

#### 1.4.2 四个核心指标（以"存活"为正类）

| 指标 | 公式 | 含义 | 逻辑回归的值 |
|------|------|--------|-------------|
| 准确率 Accuracy | (TN+TP) / (TN+TP+FN+FP) | **所有判断**的正确率 | 213/268 = 0.795 |
| 精确率 Precision | TP / (TP+FP) | **判活中**真活的比例 | 73/98 = 0.745 |
| 召回率 Recall | TP / (TP+FN) | 真存活中**被判活**的比例 | 73/103 = 0.71 |
| F1 | 2×(P×R)/(P+R) | 精确和召回的**调和平均数** | 0.73 |

##### 1.4.2.1 精确率 vs 召回率 — 天生冲突

- **精确率高** = 判存活很保守，没把握就不判 → 漏掉很多（**召回率低**）
- **召回率高** = 宁可错杀也不放过 → 很多人被误判存活（**精确率低**）

决策树就是极端例子：

| 存活精确率 | 存活召回率 |
|-----------|-----------|
| 0.81（最高） | 0.60（最低） |

精确率很高，判得很准，但只找到了 60% 的真活人
**相当于实际情况下只找到了60%存活的人，这是不可接受的**

为了综合考虑一个模型的能力，我们需要一个数值可以**均衡精确率与召回率**
`F1 Score`应运而生了

##### 1.4.2.2 F1 Score — 惩罚'偏科'

F1 是调和平均数，公式：

```
F1 = 2 × (P × R) / (P + R)
```

**调和平均的特性：两个数差距越大，结果被拉得越低。**

```
决策树:   P=0.81, R=0.60  →  F1=0.69  ← 被拉下来了
逻辑回归: P=0.74, R=0.71  →  F1=0.73  ← 两个都均衡，稳住了
```

**F1 逻辑：偏科就降分，两个都高才算高**
使用F1判断模型好坏可以**有效避免极端偏科的垃圾模型**出现

### 1.5 模型调参

每个模型创建时那些参数（如 `n_estimators=100`、`max_depth=5`）叫做**超参数**——不是从数据学来的，是手工指定的。

#### 1.5.1 GridSearchCV — 自动选取最优参数

```python
param_grid = {
    'n_estimators': [50, 100, 200],
    'max_depth': [None, 5, 10, 20],
    'min_samples_split': [2, 5, 10],
}

grid = GridSearchCV(
    RandomForestClassifier(random_state=42),
    param_grid,
    cv=5,
    scoring='accuracy',
    n_jobs=-1
)
grid.fit(X_train, y_train)
```

**它的作用是进行 36 种参数组合 × 5 折交叉验证 = 180 次训练**
**从中选出平均分最高的那组参数**

#### 1.5.2 调参结果解读

```python
grid.best_params_      # {'max_depth': 10, 'min_samples_split': 2, 'n_estimators': 200}
grid.best_score_       # 0.8330  ← 模拟考分数（交叉验证）
grid.score(X_test, y_test)  # 0.8022  ← 真考分数（测试集）
```

**模拟考 83.3% ≠ 真考 80.2%**：模拟考用的是训练集内部的交叉验证——模型对它"见过"的数据（虽然每折都换了验证集）总会表现好一点
真考用的是从未见过的测试集，分数低但**更真实**。

## II. 重点函数详解

### 2.1 数据预处理类

#### 2.1.1 划分训练/测试集：`train_test_split()`

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.3,
    random_state=42,
    stratify=y
)
```

| 参数 | 类型 | 说明 | 常用值 |
|------|------|------|--------|
| `X` | array/DataFrame | 特征矩阵 | — |
| `y` | array/Series | 标签列 | — |
| `test_size` | float (0~1) | 测试集占比 | 0.2 ~ 0.3（数据少取 0.2，数据多取 0.3） |
| `random_state` | int | 固定随机种子，保证结果可复现 | 42（任意数字都行，固定就好） |
| `stratify` | array | 按标签比例分层抽样，**强烈建议设置** | 传入 `y` |

**返回值**：

| 返回值 | 含义 |
|--------|------|
| `X_train` | 训练集特征（70%） |
| `X_test` | 测试集特征（30%） |
| `y_train` | 训练集标签（70%） |
| `y_test` | 测试集标签（30%） |

**`stratify` 为什么重要**：原始数据 38% 存活，随机切可能导致测试集里存活者只有 20% 或 50%，评估结果失真
`stratify=y` 保证切完后训练集和测试集各自的存活比例都是 38%

---

#### 2.1.2 编码：`LabelEncoder()`

```python
from sklearn.preprocessing import LabelEncoder

le = LabelEncoder()
df['col'] = le.fit_transform(df['col'])
```

| 方法 | 作用 |
|------|------|
| `fit(data)` | 扫描数据，记录所有不同类别 |
| `transform(data)` | 按字母序把每个类别换成数字（0, 1, 2...） |
| `fit_transform(data)` | 上面两步合成一步 |
| `inverse_transform(encoded)` | 数字→文字，反向还原 |

**适用场景**：只有两个值或少量值的分类列（如 Sex: male/female, Embarked: S/C/Q）

**不适用场景**：有大量不同值的列（如 Name）——每个名字一个编号，没有意义

**注意**：编号顺序按字母，不按"重要性"。`female`(f) < `male`(m)，所以 female=0, male=1

**其他**：LabelEncoder 适用于只有两种取值的类别（如 Sex）。对于三种及以上且无顺序的类别（如 Embarked），严格来说应该用 OneHotEncoder（独热编码）生成 [1,0,0]、[0,1,0]、[0,0,1]。但在特征少、树模型为主的场景下，LabelEncoder 也能工作，只是线性模型会受"虚假顺序"影响。

---

#### 2.1.3 标准化：`StandardScaler()`

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)
```

| 方法 | 做了什么 | 什么时候用 |
|------|---------|-----------|
| `fit(X)` | 计算每列的均值 μ 和标准差 σ | 只用训练集 |
| `transform(X)` | 用已有的 μ 和 σ 标准化：`(x-μ)/σ` | 训练集、测试集都用 |
| `fit_transform(X)` | fit + transform 一步完成 | **只用训练集** |
| `inverse_transform(X)` | 反向还原：`x×σ+μ` | 把标准化后的数据还原 |

**核心规则**：

```
训练集 → fit_transform()  ← 学参数 + 应用
测试集 → transform()      ← 只用训练集的参数
新数据 → transform()      ← 同上，永远不再 fit
```

**为什么**：测试集/新数据应该"被考试"，而不是"教模型怎么评分"。用 `fit_transform` 测试集 = 数据泄露。

**标准化后的效果**：每列均值 ≈ 0，标准差 ≈ 1，值域 [−3, +3] 左右。

---

#### 2.1.4 缺失值填充：`fillna()`

```python
df['Age'] = df['Age'].fillna(df['Age'].median())    # 中位数
df['Embarked'] = df['Embarked'].fillna(df['Embarked'].mode()[0])  # 众数
```

| 填充值 | 适用场景 | 特点 |
|--------|---------|------|
| `median()` | 数值列、偏态分布 | 不受极端值影响，最稳健 |
| `mean()` | 数值列、正态分布 | 会受极端值影响 |
| `mode()[0]` | 分类列 | `[0]` 取第一个众数（可能有多个并列） |

### 2.2 模型类（统一起名和参数）

**scikit-learn 里所有模型的用法完全统一，唯一的区别是创建时的参数，所有模型遵循完全相同的 API:**

```python
model = 某分类器(参数...)        # 1. 选模型
model.fit(X_train, y_train)     # 2. 学（喂题目+答案）
y_pred = model.predict(X_test)  # 3. 考（只看题目，不看答案）
```

#### 2.2.1 `LogisticRegression` — 逻辑回归

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(max_iter=1000, random_state=42)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_iter` | 100 | 求解器最大迭代次数。数据量大或特征多时默认值可能不够，设 1000 确保收敛 |
| `random_state` | None | 固定随机种子（初始化时用到） |
| `C` | 1.0 | 正则化强度的倒数。越小正则化越强（越不容易过拟合），越大越弱。调参候选人：`[0.1, 1, 10]` |
| `penalty` | 'l2' | 正则化类型。`'l2'`（默认）适合大多数场景；`'l1'` 能做特征选择 |

---

#### 2.2.2 `KNeighborsClassifier` — KNN (K-Nearest Neighbors)

```python
from sklearn.neighbors import KNeighborsClassifier

model = KNeighborsClassifier(n_neighbors=5)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `n_neighbors` | 5 | 看最近几个邻居投票。太小不稳定，太大模糊。建议奇数（避免平票）。调参候选人：`[3, 5, 7, 9, 11]` |
| `weights` | 'uniform' | `'uniform'`=每人一票；`'distance'`=近的权重大 |
| `p` | 2 | 距离度量。`2`=欧氏距离；`1`=曼哈顿距离 |

**特别注意**：KNN 的 `fit` **不训练任何东西**，只把数据存起来。真正的计算发生在 `predict` 时——对每个新样本，要算它和所有训练样本的距离。所以训练很快但预测很慢。

**标准化对 KNN 至关重要**：KNN 基于距离计算，不标准化的话大数值特征会主导距离计算。

---

#### 2.2.3 `DecisionTreeClassifier` — 决策树

```python
from sklearn.tree import DecisionTreeClassifier

model = DecisionTreeClassifier(max_depth=5, random_state=42)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_depth` | None | **最重要的参数**。None=不限制，树会疯长直到"背下"所有训练样本（过拟合）。设 3~10 为宜 |
| `min_samples_split` | 2 | 一个节点至少几个人才继续分叉。调大可以防止过度分裂 |
| `min_samples_leaf` | 1 | 每片叶子至少几个人。调大让树更简单 |
| `criterion` | 'gini' | 分裂标准。`'gini'`（基尼系数）和 `'entropy'`（信息熵）效果相近 |
| `random_state` | None | 固定随机种子 |

**决策树最危险的陷阱**：不设 `max_depth`。它会一直分裂到每片叶子只有一个样本——训练集准确率 100%，但测试集可能只有 70%。这叫**过拟合**。

---

#### 2.2.4 `RandomForestClassifier` — 随机森林

```python
from sklearn.ensemble import RandomForestClassifier

model = RandomForestClassifier(n_estimators=100, random_state=42)
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
```

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `n_estimators` | 100 | 森林里种多少棵树。越多越稳，但越慢（线性增长）。调参：`[50, 100, 200, 300]` |
| `max_depth` | None | 每棵树的最大深度。None=不限制单棵树 |
| `min_samples_split` | 2 | 节点最小分裂样本数 |
| `min_samples_leaf` | 1 | 叶子节点最少样本数 |
| `max_features` | 'sqrt' | 每棵树随机用多少特征。`'sqrt'`（默认）是经验最佳值 |
| `random_state` | int | 固定随机种子（保证 100 棵树每次一样） |
| `n_jobs` | None | 并行训练。`-1`=用所有CPU核心 |

**随机森林特有的属性**：

```python
model.feature_importances_   # 特征重要性数组（7个数，合=1）
model.estimators_            # 100棵训练好的树，可以逐个查看
```

### 2.4 调参函数

#### 2.4.1 穷举找最优：`GridSearchCV()`

```python
from sklearn.model_selection import GridSearchCV

grid = GridSearchCV(
    estimator,          # 模型
    param_grid,         # 参数字典
    cv=5,               # 交叉验证折数
    scoring='accuracy', # 评分标准
    n_jobs=-1           # 并行数
)
grid.fit(X_train, y_train)
```

| 参数 | 说明 | 常用值 |
|------|------|--------|
| `estimator` | 要调参的模型实例 | `RandomForestClassifier(random_state=42)` |
| `param_grid` | 搜索的参数空间，内容为字典格式 | `param={'n_estimators': [],'max_depth':[],...}` |
| `cv` | K折交叉验证 | 5（数据少取 10） |
| `scoring` | 评判标准 | `'accuracy'`, `'f1'`, `'roc_auc'` |
| `n_jobs` | 并行线程数 | `-1` = CPU的全部核心 |
| `verbose` | 打印进度 | 0=安静, 1=简要, 2=详细 |

##### 2.4.1.1 cv=5 交叉验证

作用:把训练集再切 5 份，轮流用 4 份训练、1 份验证，共训练五次，最终分数取五次平均值

```
折 1: [B C D E] 训练, [A] 验证 → 分数₁
折 2: [A C D E] 训练, [B] 验证 → 分数₂
折 3: [A B D E] 训练, [C] 验证 → 分数₃
折 4: [A B C E] 训练, [D] 验证 → 分数₄
折 5: [A B C D] 训练, [E] 验证 → 分数₅

最终分数 = 平均(分数₁~₅)
```
**为什么要这样做**：单次划分可能是运气（恰好切到"容易"的测试集），K折取平均更可信

##### 2.4.1.2 关键属性/方法：

有个有意思的点，下面的属性末尾都有_，这是因为：
**属性名末尾带 _ 的，表示"这个属性只有在 fit() 之后才会生成**
| 属性/方法 | 含义 |
|-----------|------|
| `grid.best_params_` | 最佳参数组合 |
| `grid.best_score_` | 最佳组合的交叉验证平均分（模拟考分） |
| `grid.best_estimator_` | 用最佳参数重新训练好的模型（可以直接去 predict） |
| `grid.cv_results_` | 所有组合的详细分数（DataFrame 格式，可分析） |
| `grid.score(X_test,y_test)` | 测试集上的准确率（真正没见过的数据）|

**注意对比`best_score_`和`grid.score(X_test,y_test)`，模拟考和正式考的区别**

GridSearchCV 默认 refit=True：在找到最佳参数后，会自动用最佳参数在整个训练集上重新训练一遍
**所以 best_estimator_ 可以直接用于预测，不需要手动再 fit**

## III. 主流模型详细对比

### 3.1 模型总览

| 维度 | KNN | 逻辑回归 | 决策树 | 随机森林 |
|------|-----|---------|--------|---------|
| **类型** | 基于距离/实例 | 线性分类器 | 单一树结构 | 集成学习（Bagging） |
| **适用场景** | 分类+回归 | **分类** | 分类+回归 | 分类+回归 |
| **训练方式** | 不训练，只记忆 | 迭代求解权重 | 递归分裂 | N 棵树并行训练 |
| **可解释性** | 低（"因为邻居投了票"） | 中（看权重符号） | **高**（树结构可视化） | 中（特征重要性） |
| **训练速度** | **极快**（不训练） | 快 | 快 | 慢（N 棵树） |
| **预测速度** | 慢（和所有样本比距离） | 快 | 快 | 中（N 棵树都要算） |
| **过拟合风险** | 低（K 大会模糊） | 低（线性假设约束） | **高**（不限制就背题） | 低（集成抗过拟合） |
| **需要标准化** | **必须**（距离计算） | 建议（帮助收敛） | 不需要 | 不需要 |
| **处理非线性** |  天然支持 |  只能线性边界 |  天然支持 |  天然支持 |
| **抗噪声能力** | 中（噪声邻居误导） | 强（线性约束平滑） | 弱（噪声导致错误分裂） | **强**（多棵树平均） |

---

### 3.2 模型对比

#### 3.2.1 KNN — 靠邻居投票

**原理**：对一个新样本，找训练集里离它最近的 K 个邻居，看这些邻居多数属于哪一类，新样本就归哪一类。

**核心直觉**："你的邻居是什么样，你大概也是什么样。"

**适用条件**：
- 样本数不太大（预测慢）
- **必须标准化**（距离对尺度敏感）
- 特征数不太多（维度灾难——高维空间里所有点都一样远）

**何时选它**：
- 数据有天然聚集性（同一类的人扎堆在一起）
- 决策边界不规则（非线性的弯弯曲曲）
- 需要一个简单、无训练的 baseline

**关键参数**：

| 参数            | 含义   | 默认 | 调参建议                          |
| ------------- | ---- | ---------|-------------------- |
| `n_neighbors` | 邻居数量 | 5 | 推荐**3~11 的奇数**。太小过拟合，太大欠拟合 |



**在泰坦尼克的表现**：

```
准确率 0.787（第三名）
存活 precision 0.74, recall 0.68, F1 0.71
```

**缺点在项目中的体现**：62% 的人死于少数服从多数，KNN 天然倾向判死亡——存活召回率只有 68%，在四个模型里较低。

---

#### 3.2.2 逻辑回归 — 稳定的 baseline

**原理**：对每个特征学一个权重 w，加权求和后通过 sigmoid 函数把结果压到 0~1，大于 0.5 判正类。

**核心直觉**："每个特征增一分或减一分存活概率，线性地影响最终结果。"

**适用条件**：
- 特征和标签存在**近似线性关系**（如：性别女 → 存活率明显更高）
- 需要概率输出（不只是 0/1，还要"存活概率 73%"）
- 需要稳定、可解释的 baseline

**何时选它**：
- 作为第一个模型跑，建立 baseline
- 特征不多、关系比较直白时
- 需要一个简单但可靠的模型

**关键参数**：

| 参数         | 含义       | 默认 | 调参建议                          |
| ---------- | -------- | ---------------------|------------------------------ |
| `C`        | 正则化强度的倒数 |  1.0 | **越小越严**（防过拟合），越大越松。过拟合时调小(0.1)，欠拟合时调大(10) |
| `max_iter` | 最大迭代次数   |  100 | 复杂数据**设 1000**，防止收敛警告                        |
| `random_state` | 随机种子	| - | 建议固定，否则结果不可复现 |


**Sigmoid 函数**：

```
σ(z) = 1 / (1 + e^(-z))

z = w₁×Age + w₂×Sex + ... + b

z 很大 →  σ≈1 → 判存活
z 很小 →  σ≈0 → 判死亡
z=0    →  σ=0.5 → 刚好在边界
```

**在泰坦尼克的表现**：

```
准确率 0.795
存活 F1 0.73（四模型最高）
```

**为什么 F1 最高**：性别和舱位等级确实对存活有强线性关系——女性 > 男性，一等舱 > 二等舱 > 三等舱
逻辑回归天然适配这种"打分制"的数据，精确率和召回率最均衡。

---

#### 3.2.3 决策树 — 可解释但爱背题

**原理**：每次找一个特征和一个阈值，把数据切成两份，重复直到满足停止条件。

**核心直觉**：问一系列是/否问题，根据答案走到最终判定

**适用条件**：
- 需要**高度可解释**（可以画出整棵树——监管、医疗场景必需）
- 特征和目标之间有明显的阈值效应（如"年龄 < 12 岁存活率突增"）
- 特征混合类型（数值 + 类别，树天然兼容）

**何时选它**：
- 你需要向非技术人员解释模型为什么这样判断
- 作为随机森林的"零件"
- 数据有很明显的 if-else 规律

**关键参数**：

| 参数 | 含义 | 默认 |调参建议 |
|------|------|------|--------|
| `max_depth`（**核心参数**） | 限制树的深度 | None | 不修改会导致无限生长，因此**必须修改**！建议3~10 |
| `min_samples_split` | 节点最少几人才能继续分裂 | 2 | 建议2-10 |
| `min_samples_leaf` | 叶子最少几人 | 1 | 1~5 |

**过拟合示意**：

```
max_depth=None:   训练集 100% ✓  测试集 70% ✗  ← 背题了
max_depth=3:      训练集 82%     测试集 79%      ← 学到了规律
max_depth=5:      训练集 85%     测试集 79% ✓   ← 甜点
max_depth=10:     训练集 92%     测试集 76% ✗  ← 开始背了
```
**max_depth=None会让一棵树随意疯长，在决策树模型下极易过拟合**

**在泰坦尼克的表现**：

```
准确率 0.791
存活 precision 0.81（最高）, recall 0.60（最低）, F1 0.69
```

**两极分化**：精确率 0.81 是四模型最高——它判存活时很谨慎，很有把握才说"活"。但召回率只有 0.60——它漏了 40% 的真存活者。偏科严重，F1 被惩罚到 0.69（四模型最低）。

---

#### 3.2.4 随机森林 — 全面选手

**原理**：种多棵决策树，但每棵树只用一部分随机数据 + 一部分随机特征。最后所有树投票决定结果。

**核心直觉**："100 个各有所长的人一起投票，比任何一个人单独判断都靠谱。"

**双重随机机制**：

```
数据随机:   每棵树只看到 ~63% 的训练样本（Bootstrap 抽样）
特征随机:   每次分裂只考虑部分特征（默认 sqrt(n_features)）
```

这两种随机性保证了每棵树各不一样——多样性是集成效果的根基。

**适用条件**：
- 追求**最高准确率**
- 数据有噪声（多棵树取平均，噪声被平滑掉）
- 不知道选什么模型——随机森林在各种场景都表现不错
- 需要特征重要性排名

**何时选它**：
- 作为最终模型
- 调参后一般是最优模型
- 需要一个"全自动"的模型（对数据假设少）

**关键参数**：

| 参数 | 作用 | 默认 | 调参建议 |
|------|------|------|-------|
| `n_estimators` | 树的数量 | 100 | 建议`[50, 100, 200, 300]`，越多越稳但越慢 |
| `max_depth` | 单棵树深度 | None | `[None, 5, 10, 20]` |
| `min_samples_split` | 节点最小分裂样本 | 2 | `[2, 5, 10]` |
| `min_samples_leaf` | 叶子最小样本 | 1 |  `[1, 2, 4]` |
| `max_features` | 每次分裂考虑的特征数 | sqrt | 保持默认 `'sqrt'` |

在随机森林中max_depth=None是作为可选项的
因为其**靠 200 棵树投票抵消单棵的过拟合**，所以单棵可以"疯"一点

**在泰坦尼克的表现**：

| | 准确率 | 存活 F1 |
|------|--------|---------|
| 默认参数 | 0.791 | 0.71 |
| 调参后 | **0.802** | 0.72 |

调参后准确率最高（唯一破 80%），但存活召回率始终~66%——现有 7 个特征区分不了那些"按常理应该死却活了"的。
提升的真正方向不是继续调参，而是构造新特征（家庭规模、姓名称谓等）

```
                    开始
                     │
                     ▼
           需要向别人解释为什么吗？
                ╱        ╲
             是           否
             │             │
             ▼             ▼

                      │            │
                      ▼            ▼

                               ╱        ╲
                             是          否
                             │            │
                             ▼            ▼
                          逻辑回归     随机森林
                          (天然适配)   (自动处理)
```

**总结选模型**：

| 场景 | 选什么 |
|------|--------|
| 第一个模型，建 baseline | 逻辑回归 |
| 需要向老板/客户解释 | 决策树（画出来） |
| 追求最高分数 | 随机森林 + GridSearchCV |
| 数据量巨大，训练要快 | 逻辑回归 |
| 不确定用哪个 | 全跑一遍，看 F1 选最优 |
| 需要概率输出 | 逻辑回归（输出天然是概率） |

### 3.4 评估指标选择

| 场景 | 选什么指标 | 为什么 |
|------|-----------|--------|
| 样本均衡 | 准确率 | 简单直接 |
| 样本不均衡 + 在乎少类 | F1（少数类） | 不会像准确率一样被多数类淹没 |
| 误报代价大（垃圾邮件→重要邮件） | 精确率 | 宁可漏掉，不能误判 |
| 漏报代价大（癌症筛查→漏诊） | 召回率 | 宁可误判，不能漏掉 |

---

### 3.5 常见坑和排错清单

| 坑 | 现象 | 原因 | 解决 |
|----|------|------|------|
| 数据泄露 | 测试集分数虚高 | 对测试集用了 `fit_transform` | 测试集只用 `transform` |
| 过拟合 | 训练集 99%，测试集 70% | 模型太复杂（决策树不设深度） | 设 `max_depth` / 增大正则化 |
| 欠拟合 | 训练集和测试集都 ~65% | 模型太简单（逻辑回归 max_iter 不够） | 加特征 / 换更强模型 |
| 标签不均 | 准确率很高但 F1 很低 | 模型只会判多数类 | 用 F1 评估 + 设 `stratify=y` |
| 收敛警告 | `ConvergenceWarning` | 逻辑回归迭代次数不够 | 增大 `max_iter` 到 1000 |
| 标准化遗漏 | KNN F1 很低 | 没标准化，大尺度特征主导距离 | 加上 `StandardScaler` |

### 3.6 泰坦尼克最终结论

| 模型 | 选它的理由 | 不选它的理由 |
|------|-----------|-------------|
| KNN | 简单 | 存活召回率低（偏向多数类） |
| **逻辑回归**  | **F1 最均衡 (0.73)**，线性关系天然适配 | 准确率不是最高 |
| 决策树 | 可解释 | 存活召回率最低 (0.60)，偏科严重 |
| 随机森林 | **准确率最高 (0.802)** | 存活召回率卡在 66%，提升方向不在调参而在特征工程 |
