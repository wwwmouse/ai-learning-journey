# 新脚本研读流程（SOP）

> **依据**：`awesome-agentic-ai-zh/docs/HOW_TO_USE.md` 的「六步学习循环」+ 本项目的实际踩坑
> **适用**：每个 `starter*.py` / `test*.py` / 示例脚本
> **目标**：60 分钟内把「能跑、读懂骨架、改得动」三件事做完
> **铁律**：一次只改一件事；做到「完成条件」才往下走（**看懂 ≠ 做得到**）

本 SOP = **课程的六步循环**（A → C）+ **两段补充**（B 读懂 / D 固化）。

---

## A 上手（10 min）— 课程第 1、2 步

### A1 先看「成功条件」（2 min）

读本题的**成功条件 / 完成条件**：课程 README 的「你会做出什么」，或 stage 文档里对应练习的完成条件。
先知道"做成什么样算过"，再动手。

### A2 直接跑原版（5 min）

```powershell
cd stage-3
python test2_multi_tool_selection.py    # 离线测试优先：$0、毫秒、确定
python starter2.py                      # 再跑真机
```

- 记基线：几个 ✅、有没有 🎉、退出码
- 正常现象：**只有 5 行 ✅ 但实际 8 条全过**（有的测试没写 `print`）
- 跑不起来先修环境，**不要改代码**

### A3 先读核心词（3 min）

读本章的「核心词」和本题的观察重点。词汇不通，代码只会越读越乱。

---

## B 读懂（25 min）— 补充段，课程没写

### B1 三分钟定位

先分清类型，读法不同：

| 类型 | 读什么 |
|---|---|
| `starter*.py`（产品代码） | 数据流、控制流、边界条件 |
| `test*.py`（验收单） | 它钉住了哪些契约、**哪些没覆盖** |

回答四问：输入/输出是什么？模型调用几次、在哪个函数？有循环吗、上限是什么？属于练习几？

然后画**数据流图**（≤5 个方框）：

```
问题 → [模型] → tool_calls → [验证] → [工具] → observation → ?
```

### B2 按重要度分层（本 SOP 的核心）

| 档 | 判据 | 读法 |
|---|---|---|
| ⭐ 核心 | 删了 agent 就不转；换框架/语言仍成立 | 逐行 + 画时序图 |
| 🟢 必读 | agent 机制所在（schema / allowlist / 验证 / 循环控制） | 记契约：输入、输出、失败形式 |
| 🟡 看关键 | 只有外层几行是 agent 知识 | 只看外层（如 `try/except`） |
| ⚪ 可跳过 | 具体业务、环境胶水 | 当黑盒，记一行签名 |

两问判据：**删掉它，agent 还能跑吗？换个场景/语言，这段还成立吗？**

**硬指标：至少一半行数应归入 ⚪。** 做不到说明还没分层。

### B3 只深读 ⭐ 和 🟢

- ⭐：**先画时序图**（`messages` 怎么变长、靠什么停），再回头看代码对答案
- 🟢：只记三样——输入、输出、失败时返回什么
- 🟡：只看"错误怎么交给模型"这类外层逻辑
- ⚪：一行黑盒签名，不进去

### B4 抓「通用四问」（判断是否学到 agent 知识）

1. **响应怎么处理**：`tool_calls` 怎么变成执行？
2. **历史怎么累积**：谁 `append`、什么顺序、怎么配平（`tool_call_id`）？
3. **错误怎么处理**：抛异常 / 返回字符串 / 分流送回模型？
4. **循环怎么停**：无 `tool_call`？`finish_reason`？`max_iter`？

答不出任何一条 → 这段没读到位；答得出 → 这就是可迁移的知识。

## C 改一处（15 min）— 课程第 3～6 步

### C1 选一个小改动（课程给的 5 类）

| 改什么 | 观察什么 |
|---|---|
| 换一个输入（空串 / 超长 / 未知值） | 验证是否拦住 |
| 新增一个工具参数，再补一条会失败的测试 | schema 与验证的对应 |
| 把 `max_iter` 调小 | 循环怎么停 |
| 暂时拿掉一个 schema 字段 | 验证会回什么 |
| 改 `description` / prompt 规则 | 模型选择是否变化（需重跑多次） |

**不要一次换模型 + 改 prompt + 加工具 + 改测试。**

### C2 先猜，再跑

用一句话写下「我觉得会发生什么」，然后跑。
不一样 → **读终端最上面第一个真正的错误**，不是最后一行。

### C3 差异化验证（强烈推荐）

故意把代码改坏一处 → 跑测试 → 看它抓不抓你。被抓到的那次，你就懂测试为什么值钱。

### C4 说出原因 + 记录

用自己的话写一句"为什么这行改变了系统"；记四栏：**改了 / 猜的 / 实际 / 结论**。

---

## D 固化（10 min）— 补充段

- 开头加**导语**：这个文件在做什么 / 和前后练习的关系 / 怎么跑
- 关键函数前标**重要度**（⭐🟢🟡⚪）
- 注释只答「**为什么**」，不复述代码
- **禁止写行号**，改用函数名/标识符引用（行号必漂移）
- 诊断用的 `print` 放进 `if` 守卫，**别抢掉后面的兜底检查**

---

## E 收尾：课程的「三句话」（必答）

1. **为什么这样写？**（例：为什么 tool result 必须放回 `messages`）
2. **拿掉它会怎样？**（例：没有 `max_iter` / schema / 参数验证会怎样）
3. **真实环境还缺什么？**（auth、eval、observability、retry、人工核准）

再补两问（本项目）：

4. 哪几种情况**工具一次都不执行**？
5. 加一个新工具要改哪几处？主流程要不要动？

**能答才往下走。** 答不出就只补那一条，不要重读整章。

---

## 卡住怎么办（课程原方）

1. 看终端**最上面第一个真正的错误**，不要只看最后一行
2. `git diff` 看自己刚改了什么；先手动还原最后一个改动，再跑一次
3. 读本题成功条件与测试名称
4. 仍不懂 → 记一行疑问，**往下走**（同样的概念会在后面的练习重复出现）

---

## 常见坑（本项目踩过的）

| 坑 | 症状 | 对策 |
|---|---|---|
| 行号引用漂移 | 注释里的行号指到别的代码 | 用函数名引用 |
| 诊断代码抢兜底 | 本该报"模型没点单"，却先 `TypeError` | `print` 放进 `if tool_calls:` |
| 相似变量用错 | `assistant` 写成了 `final_assistant` | 入历史前打印确认 |
| mock 存了引用 | 快照被后续修改污染 | `copy.deepcopy` |
| 测试全绿但行为已变 | mock 绕过了模型 | 必须补跑真机 / eval |
| 注释腐坏 | 代码改了注释没改 | 注释只写"为什么" |

---

## 时间盒

单脚本 ≤ 60 min：A 10 / B 25 / C 15 / D 10。
**一题太大就只做第一个成功条件**；不要等完美才往下走。
