# 学习总结：scikit-learn 分类实战

## 学习内容

### 数据预处理

- `pd.read_csv` 读数据
- `df.drop` 删无用列（axis=1 是删列）
- `fillna` 填缺失值（中位数比均值更稳健，不受异常值影响）
- `LabelEncoder` 文字转数字（fit 先扫描，transform 再转换）
- `StandardScaler` 标准化（fit_transform 训练集，transform 测试集——绝对不能用反）
- `train_test_split` 切数据（stratify 保持标签比例一致，random_state 固定随机性）

### 模型训练

- sklearn 的统一范式：选模型 → fit → predict → 打分
- 逻辑回归：线性、迭代求解（max_iter）、稳定 baseline
- KNN：不训练、靠邻居投票、样本不均衡时偏向多数类
- 决策树：问答题树结构、可解释性强、容易过拟合
- 随机森林：多棵树投票、抗过拟合、能输出特征重要性

### 评估

- 准确率会骗人（样本不均衡时全判多数类也能高分）
- 混淆矩阵告诉你模型在哪里犯错
- 精确率 vs 召回率是对立的：想少误报就牺牲召回，想少漏报就牺牲精确
- 交叉验证比单次划分更可信

### 调参

- GridSearchCV 自动搜索最佳参数组合
- `cv=5` 的意思是训练集内部再切 5 份轮流转
- 调参提升有上限——数据量和特征质量决定天花板


## 评估指标详解

### 准确率 ≠ 精确率

中文翻译太像，但它们是两个完全不同的东西。

以逻辑回归的混淆矩阵为例：

```
           预测死亡  预测存活
实际死亡     140       25
实际存活      30       73
```

**准确率** — 不管细节，判对的占总人数的比例：

```
(140 + 73) / 268 = 0.795
```

分母是全部 268 人。问的是"答题总分"。

**精确率（存活）** — 判存活的人里面，真活了的占多少：

```
73 / (73 + 25) = 0.745
```

分母只有被判存活的 98 人。问的是"你说它活，蒙对了没"。

**精确率（死亡）** — 判死亡的人里面，真死了的占多少：

```
140 / (140 + 30) = 0.824
```

三个数各不相同：0.795、0.745、0.824。没有一个是相等的。

极端例子——如果模型把所有人全判死亡：

- 准确率 = 165/268 = 0.616（看着还行，因为多数人本来就死了）
- 精确率（存活）= 0/0 = 不存在（一个人都没判存活，连分母都没有）

准确率 61.6%，但模型是废的——一个活人都没找到。**只看准确率就会被骗。**

### 精确率前面为什么要加"存活"

classification_report 里每个类各有一行：

```
              precision  recall  f1-score
死亡 (class 0)    0.81     0.89     0.85
存活 (class 1)    0.79     0.66     0.72
```

"精确率"不加前缀，说的是哪个？死亡的 0.81 还是存活的 0.79？前缀不是修饰语，是指定你在算谁——规则不同，数值不同。

### 准确率其实是精确率的加权平均数

用上面的数据验证：

```
精确率(死亡) = 140 / 170    （被判死亡的 170 人里，140 人真死了）
精确率(存活) =  73 /  98    （被判存活的  98 人里， 73 人真活了）

按预测人数加权：
(170/268) × (140/170) + (98/268) × (73/98)
= 140/268 + 73/268
= 213/268
= 0.795  ← 就是准确率
```

加权的过程把分母从各自的预测人数（170、98）统一成了总人数（268）。准确率不带前缀，但它是两类指标的合成体。正是因为是合成体，样本不均衡时多数类会把少数类淹没——这也是为什么必须拆开看的原因。

**准确率也是召回率的加权平均数**（按真实人数加权），两种加权都坍缩成同一个数。

### 精确率 vs 召回率：它们会打架

- **精确率高**：判存活很谨慎，宁可漏掉也不误判 → 召回率低
- **召回率高**：宁可错杀也不放过 → 精确率低

决策树就是极端例子：

| 存活精确率 | 存活召回率 |
|-----------|-----------|
| 0.81（最高） | 0.60（最低） |

判得很准，但只找到了 60% 的存活者——漏了四成。

### F1：矛盾的裁判

F1 是精确率和召回率的**调和平均**。调和平均有一个特性：**两个数差距越大，结果被拉得越低**。

调和平均公式：

```
F1 = 2 × (精确率 × 召回率) / (精确率 + 召回率)
```

用决策树的数据代入（精确率 0.81，召回率 0.60）：

```
算术平均 = (0.81 + 0.60) / 2     = 0.705
调和平均 = 2×(0.81×0.60)/(0.81+0.60)
        = 2 × 0.486 / 1.41
        = 0.972 / 1.41
        = 0.69  ← 被拉低
```

用逻辑回归代入（精确率 0.74，召回率 0.71）：

```
算术平均 = (0.74 + 0.71) / 2     = 0.725
调和平均 = 2×(0.74×0.71)/(0.74+0.71)
        = 2 × 0.5254 / 1.45
        = 1.0508 / 1.45
        = 0.73  ← 几乎不变
```

决策树精确率高但召回率拉胯，F1 直接惩罚到 0.69。逻辑回归两个都 0.7 出头但均衡，F1 稳在 0.73。

**F1 的逻辑：偏科就降分，两个都高才算高。**

### 为什么泰坦尼克只看存活类指标

891 个人里 62% 本就死了。模型闭眼判死亡，死亡指标也能好看——但那没信息量。真正难的是从人群中找出那 38% 的存活者。所以项目只关注存活类的精确率、召回率、F1，死亡类指标不列进 README。
